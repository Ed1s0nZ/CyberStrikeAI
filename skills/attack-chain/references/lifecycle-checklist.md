# 渗透/攻击链生命周期检查单（CyberStrikeAI 运行时版）

> 与 `attack-chain/SKILL.md` 配套。旧版 ops/case-init/tool-index 仪式化流程已废弃，
> 本检查单只保留对 CyberStrikeAI 运行时真实存在的约束（write_todos / 黑板 / batch_task / skill 渐进加载）。
> 日期：2026-07-27

## 启动门（每次介入本技能）

- [ ] 模式已判定：真实授权工作 / 评测计时（tsecbench、CTF、HW）
- [ ] 真实模式：scope/ROE 已一次性确认（目标范围、禁止动作、锁频阈值、禁碰系统）
- [ ] 评测模式：按 CTF 角色纪律，控制面锚点与记分板已 `pinned` 落黑板
- [ ] `write_todos` 已建 3~6 条阶段计划（侦察/验证/扩大战果/交付）

## 阶段门闩

| 阶段 | 进入条件 | 退出证据（最少一条，落黑板） |
|------|----------|------------------------------|
| S1 侦察 | 目标标识明确（URL/IP/域名/范围） | `target/*` facts：存活资产 + 指纹 + 端口 |
| S2 初始访问 | S1 产出候选入口 | `finding/*` + `record_vulnerability`（可复现 PoC） |
| S3 提权 | 已有低权限立足点 | `chain/*`：提权路径 + 凭据形态 |
| S4 横向 | 有凭据/会话材料 | `chain/*`：新控制主机 + 移动方式 |
| S5 持久化 | 授权明确包含持久化 | fact 记录机制 + 回滚方式 |
| S6 规避 | 贯穿全程 | 触发的拦截/告警签名 + 换路记录 |
| S7 影响证明 | 有控制点 | 最小化、脱敏的影响证明 |
| S8 报告 | 证据链齐 | Evidence → Finding → Path 完整 |

## 全程纪律（与编排器对齐）

- 每阶段至少一条 `upsert_project_fact`；每条可复现漏洞一条 `record_vulnerability`；压缩上下文后先从黑板恢复，不重扫
- 爆破/大字典/全端口扫描/批量验证 → `batch_task` 异步，不占 exec 通道
- 非进展 lane 到预算即杀，记 PARTIAL + coverage；任何阶段收敛后同回复列 KILL LIST
- 同一失败签名 2 次即停——换方法，不是换 payload；每假设最多 3 种不同方法
- 证据铁律见 `pentest-verification`：搜索 ≠ 漏洞，confirmed 必须带证据，负结果也落库
- 账户锁频是硬 ROE guard：per-account 尝试上限，触发即停

## 与"给一个域名全自动打穿"类技能的差异（本技能特色）

| 外部自动化包常见 | 本技能 |
|------------------|--------|
| 默认对域名狂扫 | 先模式判定 + scope 门（真实模式）/ 控制面锚点（评测模式） |
| 弱证据直接写报告 | Fact/Vuln 双轨落库，证据链 mandatory |
| 单体 prompt 干全程 | 阶段轴路由，按需加载专项，token 花在刀刃上 |
| 无时间盒概念 | 评测模式软预算 + KILL LIST + 阶段交付 |
| 结论靠对话记忆 | 结论靠黑板，压缩可恢复 |
